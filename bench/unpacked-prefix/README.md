# AGENT-95 / 2.2: отдавать движку распакованные слои

Меряет, становится ли containerd легче, если префиксный импорт несёт не gzip-блоб,
а уже распакованный tar. Сети в измеряемой секции нет: слои берутся из готовых
OCI-layout'ов, меряется только передача движку. Результаты и вердикт:
`zOptimization/Research/ResearchUnpackedPrefixLayers.md`.

Layout'ы те же, что у `bench/agent95` (`fetch_layout.py` оттуда), и лежат в
`$LAB/layouts`.

## Армы

`unpacked_layouts.py <src-layout> <out-dir> <session-id> <arm>` строит ровно то,
что эмитит `ContainerdRuntimeAdapter` — `LayerScope.ADDED_ONLY`, конфиг обрезан до
`count` diff_ids, `history` выброшен:

- `gzip` — как RIID делает сегодня;
- `tar` — пункт 2.2: префиксы несут распакованный слой, дескриптор переписан на
  (diff_id, несжатый размер, `application/vnd.oci.image.layer.v1.tar`);
- `tar-fullall` — те же префиксы, но финальный layout несёт все gzip-блобы.

Скрипт падает, если `sha256(tar)` не равен `diff_id`: на этом равенстве держится
весь пункт, проверять его надо на каждом слое, а не один раз рассуждением.

## Запуск (VM, root)

```bash
sudo ./unpacked_bench.sh                      # 3 образа x 3 раунда x 3 арма
sudo ARMS='gzip tar' ROUNDS=5 ./unpacked_bench.sh
```

Между замерами `/var/lib/containerd` стирается и containerd перезапускается, так
что каждый арм стартует на чистой ноде. Помимо времени пишется `ctr images check`:
образ может запускаться и при неполном content store, и это надо видеть.

## Оговорка про дрейф

Сравнивать армы можно только внутри одного прогона. Кросс-прогонное сравнение на
этом стенде дало +7.3 % там, где чередование армов в одной сессии показало −12.6 %
(§5 отчёта) — дрейф здесь того же порядка, что измеряемый эффект.
